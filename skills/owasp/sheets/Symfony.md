# Symfony Cheat Sheet

## Introduction

Security tips for building apps with Symfony framework: common vulnerabilities and best practices.

Symfony has built-in security mechanisms, but developers must know potential vulnerabilities and practices. Guide stresses understanding Symfony's security features and using them effectively. For newcomers and experienced developers.

## Main Sections

### Cross-Site Scripting (XSS)

XSS: malicious JavaScript injected into displayed variable. E.g., variable name = `<script>alert('hello')</script>` displayed in HTML as `Hello {{name}}` → injected script executes on render.

Symfony's default twig templates auto-protect against XSS via **output escaping**, transforming special characters in variables wrapped in `{{ }}`.

```twig
<p>Hello {{name}}</p>
{# if 'name' is '<script>alert('hello!')</script>', Twig will output this:
'<p>Hello &lt;script&gt;alert(&#39;hello!&#39;)&lt;/script&gt;</p>' #}
```

Trusted variable containing HTML: use *Twig raw filter* to disable output escaping.

```twig
<p>{{ product.title|raw }}</p>
{# if 'product.title' is 'Lorem <strong>Ipsum</strong>', Twig will output
exactly that instead of 'Lorem &lt;strong&gt;Ipsum&lt;/strong&gt;' #}
```

Twig output escaping documentation covers disabling escaping for specific block or entire template.

Non-Symfony XSS prevention: [Cross Site Scripting Prevention Cheatsheet](Cross_Site_Scripting_Prevention.md).

### Cross-Site Request Forgery (CSRF)

Symfony Form component auto-includes CSRF tokens in forms; built-in CSRF protection. Tokens validated automatically; no manual intervention.

Default: CSRF token in hidden field `_token`; customizable per form:

```php
use Symfony\Component\Form\AbstractType;
use Symfony\Component\OptionsResolver\OptionsResolver;

class PostForm extends AbstractType
{

    public function configureOptions(OptionsResolver $resolver): void
    {
        $resolver->setDefaults([
            // ... 
            'csrf_protection' => true,  // enable/disable csrf protection for this form
            'csrf_field_name' => '_csrf_token',
            'csrf_token_id'   => 'post_item', // change arbitrary string used to generate
        ]);
    }

}
```

W/o Symfony Forms: follow Symfony's manual CSRF token generation and validation. First install `symfony/security-csrf` component:

```bash
composer require symfony/security-csrf
```

Enable CSRF protection in `config/packages/framework.yaml`:

```yaml
framework:
    csrf_protection: true
```

Next, HTML Twig template with CSRF token generated by `csrf_token()` Twig function

```twig
<form action="{{ url('delete_post', { id: post.id }) }}" method="post">
    <input type="hidden" name="token" value="{{ csrf_token('delete-post') }}">
    <button type="submit">Delete post</button>
</form>
```

Configure `delete_post` route to accept `POST`, matching form. At start of controller action, validate submitted token with same token ID (`delete-post`) used by Twig. Reject missing/invalid token before any state change:

```php
$token = $request->request->get('token');
if (!is_string($token) || !$this->isCsrfTokenValid('delete-post', $token)) {
    throw $this->createAccessDeniedException('Invalid CSRF token.');
}
```

Illustrative check assumes `AbstractController` action with `Request` argument `$request`. CSRF validation doesn't authorize deletion: separately check caller's permission for target post before deleting.

Non-Symfony CSRF: [Cross-Site Request Forgery (CSRF) Cheat Sheet](Cross-Site_Request_Forgery_Prevention.md).

### SQL Injection

SQL Injection: attacker manipulates SQL query to execute arbitrary SQL → view, modify, delete data; unauthorized access or data loss.

Symfony, esp. w/ Doctrine ORM (Object-Relational Mapping), protects via prepared statement parameters. Harder to mistakenly write unprotected queries, still possible. **Insecure DQL usage**:

```php
use Doctrine\ORM\EntityManagerInterface;
use Symfony\Bundle\FrameworkBundle\Controller\AbstractController;
use Symfony\Component\HttpFoundation\Request;
use Symfony\Component\HttpFoundation\Response;

class ExampleController extends AbstractController {
    
    public function getPost(Request $request, EntityManagerInterface $em): Response
    {
        $id = $request->query->get('id');

        $dql = "SELECT p FROM App\Entity\Post p WHERE p.id = " . $id . ";";
        $query = $em->createQuery($dql);
        $post = $query->getSingleResult();

        // ...
    }
}

```

**Correct ways** to protect against SQL Injection:

- Using entity repository built-in method

```php
$id = $request->query->get('id');
$post = $em->getRepository(Post::class)->findOneBy(['id' => $id]);
```

- Using Doctrine DQL Language

```php
$query = $em->createQuery("SELECT p FROM App\Entity\Post p WHERE p.id = :id");
$query->setParameter('id', $id);
$post = $query->getSingleResult();
```

- Using DBAL Query Builder

```php
$qb = $em->createQueryBuilder();
$post = $qb->select('p')
            ->from('posts','p')
            ->where('id = :id')
            ->setParameter('id', $id)
            ->getQuery()
            ->getSingleResult();
```

Doctrine: see their documentation. Non-Symfony/Doctrine info: [SQL Injection Prevention Cheatsheet](SQL_Injection_Prevention.md).

### Command Injection

Command Injection: malicious code injected into application system and executed. See [Command Injection Defense Cheat Sheet](OS_Command_Injection_Defense.md).

Example: file removed via exec() w/o input escaping:

```php
use Symfony\Component\HttpFoundation\Request;
use Symfony\Component\HttpFoundation\Response;
use Symfony\Component\HttpKernel\Attribute\AsController;
use Symfony\Component\Routing\Annotation\Route;

#[AsController]
class ExampleController 
{

    #[Route('/remove_file', methods: ['POST'])]
    public function removeFile(Request $request): Response
    {
        $filename =  $request->request->get('filename');
        exec(sprintf('rm %s', $filename));

        // ...
    }
}
```

No input validation above. Malicious value like `test.txt && rm -rf .` possible. Mitigate: use native PHP functions such as `unlink()` or Symfony Filesystem Component `remove()` method instead of `exec()`.

PHP filesystem functions: PHP documentation or Symfony Filesystem Component documentation.

### Open Redirection

Open Redirection: app redirects users to URL from invalidated parameter; attackers redirect users to malicious sites.

Example:

```php
use Symfony\Bundle\FrameworkBundle\Controller\AbstractController;
use Symfony\Component\HttpFoundation\Request;
use Symfony\Component\HttpFoundation\Response;
use Symfony\Component\HttpKernel\Attribute\MapQueryParameter;
use Symfony\Component\Routing\Annotation\Route;

class ExampleController extends AbstractController 
{

    #[Route('/dynamic_redirect', methods: ['GET'])]
    public function dynamicRedirect(#[MapQueryParameter] string $url): Response 
    {
        return $this->redirect($url);
    }
}
```

Controller redirects per `url` query parameter w/o validation; attackers craft malicious URLs leading users to malicious sites. Prevent: always validate and sanitize user input before redirection; don't use untrusted input directly in redirect functions.

### File Upload Vulnerabilities

Arise when app doesn't properly validate/handle uploads. Guidelines for Symfony:

#### Validate file type and size

Always validate file type server-side; accept only allowed types. See Symfony validation documentation.
Limit uploaded file size to prevent denial-of-service and ensure server has resources for uploads.

PHP Attributes example:

```php
use Symfony\Component\HttpFoundation\File\UploadedFile;
use Symfony\Component\Validator\Constraints\File;

class UploadDto
{
    public function __construct(
        #[File(
            maxSize: '1024k',
            mimeTypes: [
                'application/pdf',
                'application/x-pdf',
            ],
        )]
        public readonly UploadedFile $file,
    ){}
}
```

Symfony Form example:

```php
use Symfony\Component\Form\AbstractType;
use Symfony\Component\Form\Extension\Core\Type\FileType;
use Symfony\Component\Form\FormBuilderInterface;
use Symfony\Component\Validator\Constraints\File;

class FileForm extends AbstractType
{
    public function buildForm(FormBuilderInterface $builder, array $options)
    {
        $builder
            ->add('file', FileType::class, [
                'constraints' => [
                    new File([
                        'maxSize' => '1024k', 
                        'mimeTypes' => [
                            'application/pdf',
                            'application/x-pdf',
                        ],
                    ]),
                ],
            ]);
    }
}
```

#### Use unique filenames

Unique name per uploaded file prevents overwriting existing files. E.g., combine unique identifier + original filename.

#### Store uploaded files securely

Store outside public directory to prevent direct access. If public directory used, configure web server to deny access to upload directory.

See [File Upload Cheatsheet](File_Upload.md).

### Directory Traversal

Directory/path traversal: access files/directories on server by manipulating input referencing files w/ “../” *dot-dot-slash* sequences and variations, or absolute file paths. See OWASP Path Traversal.

Protect: validate requested file location's absolute path, or strip directory info from filename input.

- Resolve base directory and requested path with `realpath()`, rejecting failures. Include directory separator in containment check so sibling such as `/storage-private` can't match `/storage`.

```php
use Symfony\Bundle\FrameworkBundle\Controller\AbstractController;
use Symfony\Component\HttpFoundation\Response;
use Symfony\Component\HttpKernel\Attribute\MapQueryParameter;
use Symfony\Component\Routing\Annotation\Route;

class ExampleController extends AbstractController 
{

    #[Route('/download', methods: ['GET'])]
    public function download(#[MapQueryParameter] string $filename): Response 
    {
        $storagePath = $this->getParameter('kernel.project_dir') . '/storage';
        $filePath = $storagePath . '/' . $filename;

        $realBase = realpath($storagePath);
        $realPath = realpath($filePath);

        if ($realBase === false || $realPath === false
            || !str_starts_with($realPath, $realBase . DIRECTORY_SEPARATOR))
        {
            throw $this->createNotFoundException();
        }

        // Use $realPath for the authorized file operation.

    }
}
```

Illustrative check assumes untrusted users can't change directories or symbolic links between validation and file access. Separately check caller's permission to access resolved file.

- Strip directory information with PHP *basename* function

```php
// ...

$storagePath = $this->getParameter('kernel.project_dir') . '/storage';
$filePath = $storagePath . '/' . basename($filename);

// ...
```

### Dependencies vulnerabilities

Dependency vulnerabilities expose app to risks. Keep all Symfony components and third-party libraries up-to-date.

Composer (PHP dependency manager) updates packages:

```bash
composer update
```

Some dependencies may contain vulnerabilities. Symfony Security Checker examines project's *composer.lock* for known vulnerabilities in installed dependencies.

Run with Symfony CLI:

```bash
symfony check:security
```

### Cross-Origin Resource Sharing (CORS)

CORS: browser security feature controlling how web apps in one domain request/interact with resources on other domains.

Symfony: manage CORS policies via `nelmio/cors-bundle`; precise CORS rules w/o changing server settings.

Install with Composer:

```bash
composer require nelmio/cors-bundle
```

Symfony Flex: installation auto-generates basic configuration file in `config/packages`. Example config for routes starting with */API* prefix.

```yaml
# config/packages/nelmio_cors.yaml
nelmio_cors:
    defaults:
        origin_regex: true
        allow_origin: ['*']
        allow_methods: ['GET', 'OPTIONS', 'POST', 'PUT', 'PATCH', 'DELETE']
        allow_headers: ['*']
        expose_headers: ['Link']
        max_age: 3600
    paths:
        '^/api': ~  # ~ means that configurations for this path is inherited from defaults
```

### Security-related Headers

Add essential security headers to responses:

- Strict-Transport-Security
- X-Frame-Options
- X-Content-Type-Options
- Content-Security-Policy
- X-Permitted-Cross-Domain-Policies
- Referrer-Policy
- Clear-Site-Data
- Cross-Origin-Embedder-Policy
- Cross-Origin-Opener-Policy
- Cross-Origin-Resource-Policy
- Cache-Control

Header details: OWASP secure headers project.

Symfony: add headers manually or automatically by listening to ResponseEvent for every response, or configure web servers like Nginx or Apache.

```php
use Symfony\Component\HttpFoundation\Request;

$response = new Response();
$response->headers->set('X-Frame-Options', 'SAMEORIGIN');
```

### Session & Cookies Management

Configure session cookies under `framework.session` in `config/packages/framework.yaml`. HTTPS app: explicitly set [`cookie_secure: true`](https://symfony.com/doc/current/reference/configuration/framework.html#cookie-secure); `auto` sets it `false` for HTTP requests, doesn't guarantee secure cookies. Keep [`cookie_httponly: true`](https://symfony.com/doc/current/reference/configuration/framework.html#cookie-httponly) to prevent JavaScript reading cookie.

```yaml
framework:
    session:
        cookie_secure: true
        cookie_httponly: true
        cookie_samesite: lax
```

Use `cookie_samesite: lax`, or `strict` where navigation flows permit. SameSite restricts cross-site cookie sending; doesn't isolate all origins. E.g., sibling subdomains with same scheme can be same-site. Retain CSRF protection for state-changing requests.

[`cookie_lifetime`](https://symfony.com/doc/current/reference/configuration/framework.html#cookie-lifetime) in seconds: `5` = five seconds, not five minutes. Cookie expiration doesn't enforce server-side session timeout. Implement server-side idle and absolute expiration per [Session Management Cheat Sheet](Session_Management.md#automatic-session-expiration).

---
Symfony manages sessions itself via its own session handling, not PHP's default via `session.auto_start = 1` directive in php.ini.
`session.auto_start = 1` auto-starts session each request, bypassing explicit `session_start()` calls. With Symfony session management, disable `session.auto_start` to prevent conflicts and unexpected behavior.

### Authentication

Symfony Security gives robust authentication: providers, firewalls, access controls. Configure in `config/packages/security.yaml`.

- **Providers**

    Fetch user info from storage types: databases, LDAP, custom sources. Get users by defined property, load corresponding user object.

    Example: Entity User Provider, uses Doctrine to fetch user by unique identifier.

    ```yaml
    providers:
        app_user_provider:
            entity:
                class: App\Entity\User
                property: email
    ```

- **Firewalls**

    Define security configurations for different app parts. Each firewall sets rules/actions for incoming requests: which routes/URLs secured, authentication mechanisms, unauthorized access handling. Can associate with specific patterns, request methods, access controls, authentication providers.

    ```yaml
    firewalls:
        dev: # disable security on routes used in development env
            pattern: ^/(_(profiler|wdt)|css|images|js)/
            security: false
        admin: # handle authentication in /admin pattern routes
            lazy: true
            provider: app_user_provider
            pattern: ^/admin
            custom_authenticator: App\Security\AdminAuthenticator
            logout:
                path: app_logout
                target: app_login
        main: # main firewall that include all remaining routes
            lazy: true
            provider: app_user_provider
    ```

- **Access Control**

    Determines which users access specific app parts. Rules = path patterns + required roles/permissions, under `access_control` key.

    ```yaml
    access_control:
        - { path: ^/admin, roles: ROLE_ADMIN } # only user with ROLE_ADMIN role is allowed
        - { path: ^/login, roles: PUBLIC_ACCESS } # everyone can access this route
    ```

### Error Handling Disclosure

Symfony apps display detailed error messages only in development environment by default; production shows generic error page. Custom error pages per HTTP status code possible. Symfony logs detailed error info for debugging.

Non-Symfony error handling: [Error Handling Cheat Sheet](Error_Handling.md).

### Sensitive data

Best way to store configurations like API keys: environment variables, dependent on application's location.
For sensitive values, Symfony's *secrets management system* additionally encodes values with cryptographic keys, stores as **secrets**.

Example: API_KEY stored as secret:

Generate cryptographic key pair. Private key file highly sensitive, don't commit to repository.

```bash
bin/console secrets:generate-keys
```

Generates file for API_KEY secret in `config/secrets/env(dev|prod|etc.)`

```bash
bin/console secret:set API_KEY
```

Access secret values in code same as environment variables.
Important: if environment variables and secrets share names, **environment variable values always override secrets**.

See Symfony Secrets Documentation.

### Summary

- No debug mode in production. Turn off by setting `APP_ENV` environment variable to `prod`:

    ```ini
    APP_ENV=prod
    ```

- Secure PHP configuration; see [PHP Configuration Cheat Sheet](PHP_Configuration.md).

- Properly configure SSL certificate in web server; enforce HTTPS by redirecting HTTP traffic to HTTPS.

- Implement security headers.

- Set file and directory permissions correctly to minimize risk.

- Regular backups of production database and critical files. Keep recovery plan to restore quickly.

- Use security checkers to scan dependencies for known vulnerabilities.

- Consider monitoring tools and error reporting to quickly identify/address production issues, e.g., Blackfire.io.
